## Idempotency (code)
- Notification: `UNIQUE(user_id, dedupe_key)` + `notify_once` swallows `IntegrityError` and rolls back.
  `dedupe_key=f"sighting:{sighting.id}"`; status: `f"status:{report_id}:{to_status}"` per finder.
- Thumbnail: `if sighting.photo_key and not sighting.thumb_key:` guard, deterministic filename `thumb_{photo_key}`, and
  `update(Sighting).where(Sighting.id == sighting.id, Sighting.thumb_key.is_(None)).values(thumb_key=thumb_key)`.

- drain_outbox: `with_for_update(skip_locked=True)`; duplicate publish after a partial failure is absorbed by the above.

## Decisions / deviations from the brief
- Build context is `../worker`, not `..`: the brief's `context: ..` + `COPY . /srv/worker` would nest the module at `/srv/worker/worker/` and `worker.celery_app` would not import.
- `up.sh` builds `api` first: the worker image is `FROM pettech-api`, and parallel compose builds race (would try to pull it).
- `docker-compose.test.yml`: `api-test` mounts `../worker:/srv/worker:ro` and the command is now `tests/unit tests/integration worker/tests`.
  `worker/tests/conftest.py` imports `_schema`/`_clean` from `tests.conftest` and defines `db_session` and `sighting_factory` (builds user/pet/report/sighting directly; `with_photo` writes a real PNG into `tmp_path` via `UPLOAD_DIR`).
- Worker uses `app.storage.upload_dir()` (env wins) instead of `get_settings().upload_dir` (lru_cached) so tests can point at `tmp_path` and api/worker agree.
- UUID strings converted with `uuid.UUID(...)` before `db.get` / `where` (task args are strings).
- `drain_outbox` catches publish exceptions, logs, stops the batch and commits the rows already sent; the brief would let the exception roll back the whole batch.
  Broker-down -> rows stay pending, task does not raise.
- `celery_app` adds `include=["worker.tasks"]` (so beat/worker register the tasks) and `broker_connection_retry_on_startup=True`.
- `_check_db` now disposes its engine (the old code leaked one per `/api/ready` call).
- Added tests beyond the brief: ready-degraded, status_changed idempotency, two drain_outbox tests, fresh-interpreter registration.

## Concerns
1. At-least-once gap: `drain_outbox` marks a row published when `.delay` returns. If the handler task then fails permanently (as in the pre-fix run), the outbox row is already published and nothing retries it. `handle_sighting_created` has `max_retries=5` but never calls `self.retry`. Left as in the brief; a reviewer may want retries or a dead-letter path.
2. No migration runner in compose: tables only exist after a manual `alembic upgrade head`. Worker logged missing-table errors until I ran it. Pre-existing, not in scope.
3. Test compose bind-mounts `../worker`; may need adjusting for the Docker-in-Docker Jenkins job (Task 11).
4. Only a sighting through the API was run in degraded mode; `report.status_changed` was covered by tests, not by hand.
