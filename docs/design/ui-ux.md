## 1. Design brief

| | |

## 2. ทิศทางภาพ: "ใบประกาศติดเสาไฟ"

สิ่งที่คนไทยใช้จริงเวลาสัตว์หายคือ **ใบ A4 ถ่ายเอกสาร แปะเสาไฟหน้าปากซอยหรือข้างตู้ 7-11** — รูปใหญ่เต็มครึ่งใบ ข้อความสำคัญไม่กี่บรรทัด เบอร์โทรตัวโตล่างสุด เราทำของจริงชิ้นนั้นให้เป็นเว็บ แต่แก้จุดอ่อนของมัน: ใบกระดาษไม่รู้ว่าเจอแล้วหรือยัง และเบอร์โทรเปิดโล่งให้ใครก็โทรมาก่อกวน

หลักสามข้อที่มาจากของจริงชิ้นนี้:

1. **รูปคือเนื้อหา ไม่ใช่ของประดับ** — ผู้พบเห็นตัดสินจากรูปอย่างเดียว ทุกหน้าจอที่แสดงประกาศต้องให้รูปกินพื้นที่มากที่สุดของบล็อกนั้น
2. **เวลาที่หายไปคือตัวเลขที่ใหญ่ที่สุดบนจอ** — ไม่ใช่วันที่ ไม่ใช่รหัสประกาศ ความเร่งด่วนของเรื่องนี้คือฟังก์ชันของเวลา: "หายไป 3 ชั่วโมง 20 นาที" ตัวโต ส่วน `2026-10-03 14:20` ตัวเล็กอยู่ใต้
3. **สถานะคือตราประทับ** — ใบประกาศที่เจอสัตว์แล้วควร "ถูกประทับ" ทับ ไม่ใช่เปลี่ยนสีจุดกลมเล็กๆ ที่มุม

### สองทิศทางที่ถูกปฏิเสธ (และเหตุผล)

| ที่ถูกเสนอ | ทำไมไม่เอา |
|---|---|
| **Navy `#0F172A` + ฟ้า `#0369A1` สไตล์ "Accessible & Ethical"** (จาก ui-ux-pro-max) | ถูกเรื่อง accessibility แต่ palette นี้คือหน้าตาเว็บหน่วยงานรัฐ/ประกันภัย ซึ่งเป็นสิ่งที่คนไทยเลื่อนผ่าน — เราเก็บ **ข้อกำหนด** ของสไตล์นี้ไว้ทั้งหมด (contrast ≥4.5:1, focus ring 3px, touch 44px, ไม่สื่อด้วยสีเดียว) แต่ไม่เอา palette |
| **Lexend + Source Sans 3** | **ไม่มีสระและวรรณยุกต์ไทย** — ตัวไทยจะ fallback ไปฟอนต์ระบบ ทำให้สระลอยและบรรทัดเหลื่อม นี่คือข้อผิดพลาดที่ร้ายแรงกว่าเรื่องรสนิยม |
| **Sarabun** (ฟอนต์มาตรฐานราชการไทย) | อ่านง่ายจริง แต่คนไทยเห็นแล้วนึกถึงหนังสือราชการทันที = ข้อเดียวกับ palette navy |
| **Perpetual micro-animation / magnetic button / infinite loop** (จาก design-taste baseline MOTION_INTENSITY 6) | ปรับลงเป็น **2** โดยเจตนา: ผู้ใช้หลักกำลังตกใจและอาจใช้เน็ตมือถือกลางถนน การ์ดที่ขยับเองตลอดเวลาทำให้กวาดตาหารูปยากขึ้นและกิน battery · สกิลระบุว่าให้ปรับตามบริบทที่ผู้ใช้ร้องขอ และ spec มี NFR accessibility ที่ชนกับ motion ตลอดเวลา |

**เหตุผลของฟอนต์:** `Anuphan` (Cadson Demak) เป็น Thai grotesque ที่มีบุคลิกชัด ปลายตัดเฉียบ ใช้เป็นหัวเรื่องได้โดยไม่ดูเป็นเอกสาร · `IBM Plex Sans Thai` เป็น humanist ที่ออกแบบมาให้อ่านยาวบนจอ มีน้ำหนักครบและมีละตินคู่กันสำหรับตัวเลข/อังกฤษ · สองตัวนี้ต่างกันพอให้แยกชั้นได้ด้วยตา และทั้งคู่มีวรรณยุกต์ครบจริง

**ตัวเลขใช้ `font-variant-numeric: tabular-nums`** ทุกที่ที่เป็นเวลา/จำนวน เพื่อไม่ให้ตัวเลขขยับตอนนับเวลา

## 4. ระบบสถานะ (ห้ามสื่อด้วยสีเดียว)

แต่ละสถานะมี **4 สัญญาณพร้อมกัน**: ข้อความไทย · icon · รูปทรงกรอบ · สี

| สถานะ | ข้อความ | icon (Phosphor) | กรอบ | สี |
|---|---|---|---|---|
| `SEARCHING` | กำลังตามหา | `MagnifyingGlass` | เส้นทึบ 2px | `--alert` |
| `HAS_LEAD` | มีเบาะแส | `MapPin` | เส้นทึบ 2px + มุมพับขวาบน | `--lead` |
| `RESOLVED` | พบแล้ว | `CheckCircle` | เส้นประ 2px + ตราประทับทับรูป | `--found` |

```
SEARCHING          HAS_LEAD            RESOLVED
┌──────────────┐   ┌─────────────┐╲    ┌ ─ ─ ─ ─ ─ ─ ┐
│ ⌕ กำลังตามหา │   │ ⚲ มีเบาะแส  │ ╲   ╎ ✓ พบแล้ว    ╎
└──────────────┘   └─────────────┘     └ ─ ─ ─ ─ ─ ─ ┘
```

ประกาศที่ `RESOLVED` ได้ตราประทับ **ทับบนรูป** เฉียง 8° ทึบแสง 90% ข้อความ "พบแล้ว" + วันที่ — เป็นสัญญาณเดียวที่อ่านได้แม้เห็นแค่รูป thumbnail และตอบ pain point ของ lab ตรงตัว ("ประกาศเก่ายังถูกแชร์แม้พบสัตว์แล้ว")

## 5. โครงหน้าจอ

Layout: มือถือคอลัมน์เดียว `px-16px` · ตั้งแต่ 768px ขึ้นไปใช้ grid `3fr 2fr` แบบไม่สมมาตร (ไม่ใช่การ์ดสามใบเท่ากัน) · เนื้อหายาวจำกัดที่ 68ch

- รูปเป็นสี่เหลี่ยม 4:3 กว้าง 40% ของแถวบนมือถือ — ใหญ่พอให้จำลายสัตว์ได้
- ตัวเลขเวลาที่หายไปคือ `--t-clock` น้ำหนัก 700 เป็นสิ่งที่ตาเห็นก่อน
- แถวคั่นด้วย `border-top: 1px var(--rule)` ไม่ใช้เงาและไม่ใช้การ์ด
- **empty state:** "ยังไม่มีประกาศในเขตนี้ — ลองเลือกเขตอื่น หรือดูทุกเขต" + ปุ่มล้างตัวกรอง
- **loading:** skeleton ที่เป็นสี่เหลี่ยมรูป + สองบรรทัด ขนาดเท่าของจริง (กัน layout shift) ไม่ใช้ spinner วงกลม

|---|---|---|
| `409 REPORT_CLOSED` | แถบ alert ด้านบนฟอร์ม + ปุ่มเปลี่ยนเป็น disabled ข้อความ "ประกาศนี้ปิดรับเบาะแสแล้ว" + ลิงก์ไปประกาศอื่นในเขตเดียวกัน | ห้าม redirect ทิ้ง · ห้ามล้างข้อความที่พิมพ์ |
| `422 VALIDATION` | ข้อความสีแดงใต้ช่องนั้น + กรอบช่องหนาขึ้น + icon และ **auto-focus ช่องแรกที่ผิด** | ห้ามแสดงรวมด้านบนอย่างเดียว |
| `422` เรื่องรูป | ข้อความใต้ปุ่มเลือกรูป "รับเฉพาะไฟล์รูป PNG, JPEG หรือ WebP ขนาดไม่เกิน 5 MB" + ล้างไฟล์ที่เลือกไว้ | ห้ามปล่อยให้ชื่อไฟล์ค้างอยู่ทำให้เข้าใจว่าแนบสำเร็จ |
| `401 AUTH_REQUIRED` | พาไปหน้าเข้าสู่ระบบ **พร้อมเก็บฟอร์มไว้ใน sessionStorage** และกลับมาเติมให้หลัง login | ห้ามให้พิมพ์ใหม่ทั้งหมด |
| กำลังส่ง | ปุ่ม disabled + ข้อความ "กำลังส่ง…" + spinner ในปุ่ม | ห้ามให้กดซ้ำได้ (แต่ถ้ากดซ้ำก็ยังปลอดภัยเพราะ Idempotency-Key เดิม) |
| สำเร็จ | กลับไปหน้ารายละเอียด เบาะแสใหม่เลื่อนเข้า timeline จากซ้าย 180ms **นี่คือ motion เดียวในแอป** | ห้ามใช้ toast ที่หายไปแล้วไม่เหลือร่องรอย |

### 5.4 แจ้งสัตว์หาย `/reports/new`

สามบล็อกบนหน้าเดียว ไม่ทำ wizard หลายขั้น (ผู้ใช้กำลังตกใจ การแบ่งหน้าเพิ่มโอกาสหลุดกลางทาง): **สัตว์ตัวไหน** (เลือกจากที่มี หรือเพิ่มใหม่ inline) → **หายเมื่อไหร่ ที่ไหน** (เวลาตั้งค่าเริ่มต้นเป็น "1 ชั่วโมงที่ผ่านมา" ปรับได้ · เขตเป็น datalist ของ 50 เขต กทม.) → **ลักษณะเด่น** (helper text: "สิ่งที่ทำให้คนแยกตัวนี้จากตัวอื่นได้ เช่น ปลอกคอ รอยแผล หางด้วน")

### 5.5 ประกาศของฉัน `/me/reports`

### 5.7 / 5.8 เข้าสู่ระบบ · สมัครสมาชิก

ฟอร์มเดียวกลางจอบนมือถือ · desktop ซ้ายเป็นฟอร์ม ขวาเป็นข้อความอธิบายสั้นว่าทำไมต้องสมัครก่อนส่งเบาะแส (ตอบข้อโต้แย้งที่คนจะมีจริง: "แค่จะบอกว่าเห็นแมว ทำไมต้องสมัคร") — เหตุผลที่เขียนบนจอ: "เพื่อให้เจ้าของตอบกลับคุณได้โดยไม่ต้องเปิดเบอร์โทรของใครเลย"

- รหัสผ่านมีปุ่มแสดง/ซ่อน · `autocomplete="email current-password"` ครบ
- login ผิด: `role="alert"` "อีเมลหรือรหัสผ่านไม่ถูกต้อง" — **ไม่บอกว่าผิดช่องไหน** และ focus กลับไปช่องอีเมล

## 6. ปุ่มและลำดับความสำคัญ

| ชั้น | หน้าตา | ใช้กับ |
|---|---|---|
| หลัก | พื้น `--ink` ตัวอักษร `--paper` radius 3px สูง 48px | ปุ่มเดียวต่อหน้า: ส่งเบาะแส / แจ้งสัตว์หาย / เข้าสู่ระบบ |
| รอง | พื้นโปร่ง เส้นขอบ 1.5px `--ink` | ปิดประกาศ · ยกเลิก |
| ทำลาย | ตัวอักษร `--alert` เส้นขอบ `--alert` | เปิดประกาศใหม่หลังปิด (ต้องยืนยัน) |
| ลิงก์ | ขีดเส้นใต้เสมอ (ไม่ใช้สีเพียงอย่างเดียว) | นำทางทั้งหมด |

`:active` ใช้ `transform: translateY(1px)` ไม่ใช้เงาเรืองแสง · `:focus-visible` ใช้ `outline: 3px solid var(--focus); outline-offset: 2px` ทุก element ไม่มีการลบ

## 7. Accessibility — เงื่อนไขผ่าน/ไม่ผ่าน

- [ ] contrast: `--ink` บน `--paper` = 14.8:1 · `--ink-2` = 6.2:1 · `--ink-3` = 4.6:1 · ทุกสีสถานะบน wash ของตัวเอง ≥ 4.5:1
- [ ] ทุกสถานะอ่านได้โดยไม่ใช้สี (ข้อความ + icon + รูปทรงกรอบ)
- [ ] ทุก error มี `role="alert"` และ focus ย้ายไปช่องแรกที่ผิด
- [ ] touch target ≥ 44×44px ทุกปุ่มรวมปุ่มลบรูป
- [ ] `prefers-reduced-motion` ตัด motion เหลือ 1ms
- [ ] ฟอนต์ไทยมีวรรณยุกต์ครบ · body ≥17px · line-height 1.75
- [ ] zoom 200% ไม่มี horizontal scroll · ไม่มี `maximum-scale`
- [ ] รูปสัตว์ทุกใบมี alt ที่มีความหมาย: `alt="แมวขาว ปลอกคอแดง ชื่อขาวมณี"` ไม่ใช่ `alt="รูปสัตว์เลี้ยง"`
- [ ] `lang="th"` บน `<html>` และ `lang="en"` ครอบเลขอังกฤษ/ชื่อระบบถ้ามี
- [ ] ทดสอบที่ 375px · 768px · 1024px · 1440px และ landscape

## 8. สิ่งที่ตั้งใจไม่ทำ

ไม่มี dark/light toggle แบบ manual (ตามระบบพอ) · ไม่มี infinite scroll (ใช้ปุ่ม "ดูเพิ่ม" เพื่อไม่ให้ตำแหน่งหาย) · ไม่มีแผนที่ (ตัดตาม D2) · ไม่มี avatar ผู้ใช้ (ไม่ต้องการและเป็นข้อมูลส่วนตัวเพิ่ม) · ไม่มี toast สำหรับเหตุการณ์สำคัญ (ใช้ state บนหน้าที่อยู่ต่อ) · ไม่มี skeleton shimmer ที่วิ่งตลอด (ใช้ pulse จางๆ หรือนิ่ง)
