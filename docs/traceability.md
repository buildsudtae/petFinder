# Traceability Matrix — ตามหา (Lost Pet Finder)

เอกสารนี้ผูกทุก requirement เข้ากับเกณฑ์ตรวจรับ โค้ดที่ทำจริง และหลักฐานจากเทส
**ชื่อเทสในเครื่องหมาย backtick ถูกตรวจอัตโนมัติ** โดย `api/tests/unit/test_traceability_doc.py`
(เทสจะ fail ถ้าเอกสารอ้างชื่อ Python test ที่ไม่มีอยู่จริง หรือขาดแถวของ requirement ใด)

## วิธีรันหลักฐาน

| ชุด | คำสั่ง | หมายเหตุ |
|---|---|---|
| backend unit + integration + worker | `./scripts/test.sh` | Postgres จริงใน container |
| concurrency (ผ่าน Traefik, 2 replicas) | `./scripts/race.sh` | `api/tests/concurrency/` ถูกข้ามถ้าไม่มี `BASE_URL` จึงไม่รวมใน `test.sh` ต้องมี stack รันอยู่ |
| frontend | `cd web && npm test` | อ้างด้วย path + ชื่อเรื่อง ไม่ใช่ backtick (ตัวตรวจ Python ไม่ตรวจชุดนี้) |
| smoke บน stack ที่ deploy | `./scripts/smoke.sh` | อ้างด้วยชื่อขั้นตอน (`say "..."`) |

เทสที่ทำเครื่องหมาย (race) = รันผ่าน `./scripts/race.sh` เท่านั้น

## ช่องว่างที่ยอมรับตรงๆ

1. **FR-02** — ไม่มีเทสที่กรองด้วย `species`; ตัวกรอง `district` ไม่มีเทสที่พิสูจน์การตัดประกาศอื่นออก ไม่มีการค้นหาด้วยข้อความ (ไม่อยู่ใน scope ที่ implement)
2. **C5** — พิสูจน์ระดับ integration/unit เท่านั้น ยังไม่มีการทดลองหยุด broker/worker บน stack ที่รันจริงแล้วตรวจการระบายคิวต่อเนื่อง
3. **Frontend** — มีเทสเฉพาะ `ErrorBanner` และ `NewSighting` (6 เทส) หน้า `ReportList`, `ReportDetail`, `Relay`, `NewReport`, login/register ไม่มีเทส frontend; หลักฐานของหน้าเหล่านั้นมาจากเทส API และ smoke เท่านั้น
4. เทส concurrency ต้องรันแยกด้วย `./scripts/race.sh` และต้องมี stack อยู่ ไม่อยู่ใน `./scripts/test.sh` / pytest เริ่มต้น
